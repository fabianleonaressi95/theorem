# T060 — A coordinate-defined chain map from the filled Kathara complex to Q3

**Status:** explicit candidate construction with exact algebraic verification encoded in tests; not canonical and not yet computationally run in this change. It establishes a chain-map candidate, not a physical identification of Kathara with the I Ching.

## 1. Source and target

The source is the filled planar Kathara complex from T059:
\(\dim(C_0,C_1,C_2)=(12,21,10)\).

The target is the full cubical 2-skeleton of the trigram cube \(Q_3\):
8 vertices, 12 edges, and 6 square faces. Vertices are encoded by integers 0,...,7, with bit 0, bit 1, bit 2 corresponding to the three trigram lines (bottom to top). Target edges are oriented from bit 0 to bit 1 in the varying coordinate. Each square face is oriented by the cycle obtained by increasing the lower varying bit, then the higher varying bit, then reversing the first, then reversing the second.

## 2. Vertex map

For a Kathara center \(v\) with planar coordinate \((x_v,y_v)\), set

\[
\pi_0(v)=b_0+2b_1,\qquad
b_0=\mathbf 1_{x_v>0},\quad
b_1=\mathbf 1_{y_v\ge4},\quad b_2=0.
\]

The threshold \(y=4\) is the AzurA midline in the adopted embedding. Thus this is a geometric quadrant projection to the square face \(b_2=0\) of \(Q_3\). It is intentionally coarse: the twelve centers map to four cube vertices. It is a declared modeling choice, not a uniquely forced map.

## 3. Edge and face maps

For each source edge \(u\to v\), map it to the canonical shortest cube path from \(\pi_0(u)\) to \(\pi_0(v)\), flipping differing bits in order 0,1,2. The resulting integral 1-chain defines the corresponding column of \(S_1\).

For each source 2-cell, its mapped boundary is a closed 1-chain supported on the square face \(b_2=0\). The cycle group of that square graph is generated by its oriented boundary \((0,1,3,2)\). Define the corresponding column of \(S_2\) as the integer coefficient of that generator; all other target square-face coefficients are zero.

The matrices have shapes:
\[
S_0:8\times12,\quad S_1:12\times21,\quad S_2:6\times10.
\]

## 4. Chain-map conditions

The required commuting identities are

\[
\boxed{B_1^{Q_3}S_1=S_0B_1^K},\qquad
\boxed{B_2^{Q_3}S_2=S_1B_2^K}.
\]

The first holds edge by edge because each target path has boundary equal to its endpoint difference. The second holds face by face because each mapped face boundary is a cycle in the target square and is therefore an integer multiple of that square's oriented boundary.

The implementation constructs the matrices over the integers and tests both identities entry by entry.

## 5. Interpretation and limitations

- This is a valid candidate chain map if the implementation tests pass; it is not a canonical or injective identification.
- The map factors through a single square \(Q_2\subset Q_3\). It therefore does not yet use the third trigram bit and cannot establish a genuinely three-directional trigram structure.
- It does not establish a chain map to the full Q6 hexagram complex.
- It does not derive the Krist-All operator, the supergolden transfer matrix, or any physical dynamics.
- The next meaningful refinement is to derive a non-degenerate third bit from source incidence data, rather than inventing a label assignment, and then test whether a chain map using all three cube directions exists.
